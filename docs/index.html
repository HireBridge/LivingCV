alex-tscrate

github pypi

Long-term memory for AI agents. A git-backed personal wiki that any MCP client reads and writes to, so knowledge compounds across sessions instead of being re-derived by RAG every time.

raw sources are read, never edited — the agent owns the wiki layer entirely

Design decision

Storage is plain git-backed markdown, not a database. That means any Obsidian vault pointed at the same folder gets graph view and backlinks for free, zero extra code written for it.

What's real

9 MCP tools over stdio or HTTP, multi-user server mode with per-user bearer tokens stored as SHA-256 hashes (never plaintext), a read-only web reader, and git hosting per user.

Retrieval honesty

Full-text search is lexical, not semantic. Curated pages retrieve well; dumping unfiltered logs into it would degrade retrieval quality, so the design rewards a maintained wiki over a firehose.

$pip install alex-tscrate && alex-tscrate init

alex-mosaiq

github npm

A 51-tool MCP server that runs an end-to-end pipeline: source postings, score JDs, tailor and render resumes, draft outreach, track the whole thing in SQLite.

one process, one DB — every mutation serializes through a single write lock

Design decision

Most tools default to chat mode: the server returns the rubric and context, the connected model reasons, then calls the tool again to persist. No API key required by default.

Hard-coded safety rail

A leakage scan runs inside resume rendering before persistence. A detected leak fails the call outright, not a prompt asking the model to be careful.

Multi-client, one truth

One server process shared concurrently by Claude Desktop, Claude Code, opencode, and Gemini CLI against the same DB, with a fresh MCP protocol instance per HTTP request so responses never cross-route between clients.

$npx job_ops-mcp@latest init

alex-edgeplan

github pypi

A cost-focused multi-agent simulation engine for narrative and opinion forecasting: aggressive batching, sparse activation, and strict model routing instead of running every agent at full cost.

alex-edgeplan bench reports cost_ratio, quality_delta, and runtime_ratio, lean vs naive activation

Design decision

Only a bounded fraction of agents reason per tick, chosen by trigger heuristics, instead of every agent running every round. State is hybrid: numeric mood/energy/attention plus semantic memory backed by SQLite with vector search.

Measured, not claimed

The benchmark harness runs identical cases in lean and naive modes and reports the cost/quality tradeoff as a number, not a marketing line.

Failure handling

All model traffic routes through one chokepoint. Live responses are schema-validated with one repair attempt; anything still invalid falls back to a logged mock rather than corrupting the run silently.

$pip install alex-edgeplan && alex-edgeplan smoke

alex-tinyrender

github pypi

Hierarchical coding CLI. A frontier model plans and reviews; a local Ollama model writes the code, at zero incremental cost on a bring-your-own-subscription setup.

plan → draft → QA, with bounded revise and escalate loops

Design decision

A plan cache keyed on (task, skeleton, planner model, drafter model) skips replanning on repeat runs. Planner calls stay short, 5–20k input tokens, so two or three barely dent a Claude Pro or ChatGPT Plus quota.

Real cost number

A typical task costs 4 planner calls (1 plan + 3 QA rounds) against a subscription quota instead of metered API tokens, roughly $0.01–0.15 on the API path.

Honest constraint

Diffs print to stdout and never auto-apply. Every change needs manual review before it touches disk, a deliberate limit, not a missing feature.

$pip install alex-tinyrender && alex-tinyrender init --wizard
